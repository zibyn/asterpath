# 输出风格是与智能体档案正交选择、追加在档案正文之后的提示词文件

**Status**: accepted (2026-10-26)
**来源**: [#188](https://github.com/zibyn/asterpath/issues/188)

## Context

智能体档案（ADR-0051）的正文就是会话的基础提示词：选一份档案，就整体换掉基础提示词。用户还想要另一种调整：保留编码指令，只换语气与输出形式，例如更简洁、更偏教学。Claude Code 的 output style 是这类需求的参照，它与 `--agent` 分开选择。

如果用档案本身表达这种调整，有两条路：档案之间继承（`extends`），或者让每种语气与每种职业的组合各写一份档案。前者要处理继承链、循环与跨级继承；后者是 N×M 个文件。

内置默认档案的正文里也有输出要求，叠加的内容可能与之冲突。

## Decision

- **输出风格是独立的一类命名 Markdown 文件**，与智能体档案正交选择：一个会话选零或一份档案、零或一份风格，任意组合。档案之间没有继承关系。
- **纯追加**：风格正文追加在档案正文之后，不切分、不替换档案正文的任何一段。拼接处的框定语说明风格优先于上文的输出要求。
- **拼接位置**：档案正文 → 输出风格 → `AGENTS.md` → 技能索引。风格与档案同属应用提供的基础层，项目指令在其后。
- **风格只有正文与描述**：frontmatter 只接受 `description`，带模型、工具或其他字段是错误。档案不能声明默认风格。
- **来源、优先级与解析时机与档案相同**：用户级、项目级、内置三级，同名时项目级优先；会话创建时解析一次，随 `SessionCreated` 落盘，恢复不重读，会话中途不切换。风格没有权限字段，项目级风格与 `AGENTS.md` 同等对待。

## Consequences

- 语气与职业分开维护：一份风格可以配任何档案，档案格式保持 ADR-0051 的「正文是一整块提示词」。
- 风格与档案正文冲突只靠位置与框定语解决，档案作者应让正文里的输出要求保持通用，避免与风格硬冲突。
- 子智能体继承父会话的 system，因此也带上父会话的风格。
- 项目级风格与 `AGENTS.md` 一样，能随仓库改变模型看到的提示词，但拿不到任何权限。

## Considered alternatives

- **档案继承（frontmatter `extends`）**：叠加内容仍是档案，要处理继承链、循环与项目级继承用户级；一种语气配多个档案时还要多份文件。
- **风格替换档案正文的某一段**（如 `# Output`）：档案正文要遵守隐含的段落约定，用户自写的档案也受约束。
- **选风格时去掉编码指令**（Claude Code 的默认行为，靠 `keep-coding-instructions` 保留）：与「只换语气、保留编码指令」的需求相反。
- **风格放在 system 最后**：靠后影响更大，但会压过项目 `AGENTS.md` 里的指令。
- **风格可以固定模型或收窄工具**：那就是另一份档案，破坏正交。
