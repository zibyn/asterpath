# 服务端工具按 provider 声明，文件引用绑定 provider，结构化输出是请求约束

**Status**: accepted (2026-10-24)
**来源**: [#96](https://github.com/zibyn/asterpath/issues/96)
**修订**: [ADR-0010](0010-canonical-protocol-model.md) 的请求模型（新增服务端工具声明、结构化输出与文件片段）

## Context

两家供应商都提供服务端执行的内置工具（web search、web fetch、code execution 等）、按 JSON schema 约束输出的结构化输出，以及文件输入（内联、URL 或供应商文件存储里的 ID）。规范协议此前只能解析并同 provider 回放服务端工具的调用与结果，宿主却无法声明它们；也没有结构化输出与文件片段。

约束：
- 服务端工具的配置形状各家不同且演进快（带日期的 type 名）；框架不执行、不审批它们。
- Anthropic 回放 thinking 时，若顶层 `tools` 变化会被拒绝；本地用工具集指纹近似这一校验（ADR-0010、ADR-0030）。已有日志里的指纹不能因本决定而失配。
- 供应商文件 ID 只在上传它的供应商处有意义。
- 文件是用户可见内容，与不透明 reasoning 不同：丢掉或替换它会改变对话语义。

## Decision

- **服务端工具是请求配置，不是 `ToolDescriptor`**：宿主按 provider 分键声明供应商原始 JSON（与 `provider_options` 同形），adapter 只取本 provider 的条目，原样追加到自家工具数组，不校验内容。工具注册表、审批、执行管线不感知它们；`tool_choice` 不指向它们。只支持服务端执行的工具；要求客户端执行的供应商工具不在此机制内（客户端工具走 `ToolDescriptor`）。
- **服务端工具与工具 `strict` 进入工具集指纹，但只在存在时**：声明为空、`strict` 未设置时，指纹与此前逐字节相同，旧日志的推理绑定不受影响。
- **能力不匹配返回 `Unsupported`**：声明了本 provider 的服务端工具而模型规则不支持时、请求结构化输出而模型不支持时、请求含文件而模型不支持或 media type 不被接受时，adapter 在发出 HTTP 前返回 `Unsupported`。
- **结构化输出是请求约束，产出仍是普通消息文本**：框架不解析、不校验、不重试，归宿主。adapter 一律请求严格模式。
- **文件引用绑定 provider；跨 provider 返回 `Unsupported`，不丢弃、不占位**：宿主负责改为内联或重新上传。上传与删除供应商文件归宿主。

字段形状、wire 映射、指纹的具体拼接方式见 protocol.md。

## Consequences

- 宿主可以在不扩展规范类型的情况下使用新出的服务端工具版本。
- 服务端工具配置错误（含误放客户端执行的工具）由供应商以 400 暴露，框架不预检。
- 切换 provider 时，含供应商文件引用的历史会让请求失败，直到宿主改写；这是有意的显式失败。
- 结构化输出的 schema 若不满足供应商严格模式的约束，由供应商报错。

## Considered alternatives

- **服务端工具作为 `ToolDescriptor` 的一种 kind**：loop 的执行、审批、超时、截断字段对它们全无意义，并会让工具管线按种类分支。
- **规范化每种服务端工具的配置**：规范类型随供应商 API 膨胀，新版本工具要等框架发版。
- **跨 provider 时丢弃文件片段或渲染占位**：静默改变用户可见内容，违反 ADR-0010 不静默降级的原则。
- **框架解析结构化输出并在失败时重试**：解析、校验与重试策略是宿主策略。
