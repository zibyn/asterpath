# 输出风格不进入子会话

**Status**: accepted (2026-10-26)；部分取代 [ADR-0052](0052-output-styles-are-orthogonal-appended-prompt-files.md)「子智能体继承父会话的 system，因此也带上父会话的风格」
**来源**: [#190](https://github.com/zibyn/asterpath/issues/190)

## Context

输出风格（ADR-0052）追加在根会话的档案正文之后，调整的是给人看的语气与输出形式。子会话的输出交给父会话的模型，不直接给人看。ADR-0053 已据此规定：选了档案的子会话由应用整份组装 system，不加风格。

不选档案的子会话仍然原样拷贝父会话的 system，风格跟着进去。对讲解类风格，这只是浪费 token；对要求「把一小段代码留给用户写」的教学类风格，子会话会把活留给一个不存在的人，父会话拿回残缺的结果。子会话收到的第一条消息就是 task 原文，模型分不出自己是不是子智能体，风格正文无法自行规避。

内核把 system 当作不透明的 `Vec<Part>`，分不出哪一段是风格。

## Decision

- **风格不进入子会话**：子会话的 system 不含父会话的输出风格，无论是否选了档案。
- **应用提供不带风格的基础 system**：应用的环境适配器（ADR-0037）在会话环境里与可选档案列表并列，额外给出一份「不选档案时子会话用的 system」。本地应用的组装方式与根会话相同，只是不加风格：档案正文、`AGENTS.md`、技能索引、档案索引。
- **不选档案的 fresh 子会话用这份 system**；环境里没有这一项时（应用未提供），沿用父会话的 system，行为与现在一致。子会话实际使用的 system 照旧写进 `ChildSessionSpawned`，恢复时不重新解析。
- **fork 子会话例外，沿用父会话的 system**：fork 的意义是延续父会话的上下文并复用其缓存前缀（ADR-0008、ADR-0033），换掉 system 会让父会话的历史接在另一份 system 后面。fork 子会话因此可能带着风格。
- 内核仍然不解析 system，也不知道风格的存在；分出风格是应用的事。

## Consequences

- 风格的作用范围收窄到根会话与 fork 出的会话，即直接面对人的会话；教学类风格因此可以只为人写。
- 不选档案的 fresh 子会话的 system 与父会话不再逐字节相同：父会话选了风格时，二者相差风格这一段。
- 会话环境多一项；SDK 应用不提供它时一切照旧，风格本来就是本地应用的概念。
- 应用配置成 fork 默认时，风格仍会进入子会话；本地应用不用 fork 默认。

## Considered alternatives

- **接受风格进入子会话，由风格正文兜底**：子会话收到的只有 task 原文，模型无法判断自己是子智能体，兜底不可靠。
- **内核在派生子会话时给 task 加一句「你是子智能体」**：内核往模型可见内容里注入文本，与 system 由应用给出的分工（ADR-0053）不一致，也只是另一种兜底。
- **内核按标记从 system 里剥掉风格段**：内核要理解 system 的结构，并和应用的拼接格式绑死。
- **fork 子会话也换成不带风格的 system**：父会话历史接在另一份 system 后面，且失去缓存前缀复用。
