# 会话环境由宿主适配器按会话解析，子进程默认不继承进程环境

**Status**: proposed (2026-10-25)
**调研**: [design-audit-2026-10-25.md](../research/design-audit-2026-10-25.md)、[kernel-host-boundary-audit.md](../research/kernel-host-boundary-audit.md)

## Context

工作区工具在 `AsterpathBuilder` 上构造时绑定根目录，`SessionSpec` 只按名字从注册表选工具；参考 CLI 用 `set_current_dir` 把工作根设为进程当前目录，工具、技能根、沙箱可写根都读它。于是一个 `Asterpath` 只能服务一个工作根，一个进程只能有一个。web 以库方式内嵌内核、单进程服务上千用户，每个用户有自己的工作目录与凭据，这条路走不通。

bash 工具与 MCP stdio 服务继承整个进程的环境变量。内嵌进 web 进程后，进程里的密钥会进入模型能执行的 shell。

参考：Codex 与 opencode 把工作目录放在 thread / 请求级；Claude Code 与 pi 用进程 cwd，所以一进程一工作目录。

## Decision

- **会话环境是一个适配器**：宿主在 builder 上注册。创建或打开会话时，引擎把该会话的宿主元数据交给它，得到这个会话的工具集、沙箱策略与子进程环境变量。内核不知道「工作根」，怎样从元数据得到环境是宿主的事。
- **子会话继承父会话的环境**，不重新解析。
- **环境不落日志**：每次打开按元数据重新解析；与上次不同的工具集按工具变更处理（ADR-0030）。
- **子进程默认不继承进程环境**：工具与 MCP stdio 启动子进程时只传会话环境给出的变量和一份最小白名单（如 `PATH`、`HOME`、`LANG`）。没有注册会话环境时同样按隔离处理。
- **内核不改进程状态**：不读也不写进程当前目录。

## Consequences

- 一个 `Asterpath` 可以承载不同工作根、不同凭据的会话；宿主不再需要路由工具或 `set_current_dir`。
- 参考 CLI 的行为变化：bash 里看不到用户 shell 的环境变量，除非配置放行，需要写进发布说明。
- 打开会话多一次适配器调用；同一工作根的工具实例由宿主自行缓存，缓存要有上限。
- 工具集指纹会因环境解析结果变化而变化，宿主要保证同一元数据解析出同样的工具描述。

## Considered alternatives

- **宿主的路由工具**：每个工具名注册一个转发工具，按会话元数据找工作根。子会话不继承元数据，沙箱策略也不随之路由。
- **每个工作根一个 `Asterpath`**：存储与调度被切成多份，上千用户时实例无限增长。
- **工作根作为内核概念**：内核要理解路径与目录约定，web 场景的「工作区」不一定是本地目录。
- **默认继承进程环境，由宿主选择过滤**：fail-open，内嵌时漏配即泄密。
