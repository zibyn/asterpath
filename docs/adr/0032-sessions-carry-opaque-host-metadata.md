# 会话携带不透明的宿主元数据

**Status**: accepted (2026-10-24)；「之后不可变」部分取代 by [ADR-0044](0044-host-metadata-is-patchable.md)
**来源**: CLI 重设计（[packaging.md](../design/packaging.md) §4，[对比研究](../research/cli-codex-vs-claude-code.md)）

## Context

参考 CLI 改为对齐 Codex / Claude Code：`--continue` 续当前目录最后活动的会话，`-r` 列出当前目录的会话供选择，会话可以命名。两者都按工作目录过滤会话列表，都支持按名字查找。

现状：目录项只有会话、父会话、创建时间与最后活动时间（[ADR-0023](0023-storage-holds-log-and-catalog-wake-by-fold.md)），不含标题；facade 没有列会话的 API。工作区刻意不进入内核：工具按宿主给的根目录构造，`ToolContext` 与日志里都没有工作目录（packaging.md §2）。

宿主要按目录和名字找会话，信息只能放在三处：内核日志与目录、宿主自己的索引、或者不存。

## Decision

- **会话创建时可以附上一组字符串键值对**（宿主元数据）。它记进 `SessionCreated`，之后**不可变**，没有修改它的记录。
- **框架只保存和列出，不解释**。键与值的含义归宿主；内核不按它路由、恢复、唤醒或计算用量，它也不进入模型可见的配置或请求。
- **目录项携带元数据**，facade 提供列出会话的 API（按父会话过滤、分页，与存储契约的目录查询同形）。排序与按键过滤由宿主在结果上完成。
- **子会话不继承**父会话的元数据：子会话由框架创建，宿主没有机会写入。会话分叉（[ADR-0033](0033-session-fork-reuses-context-fork-snapshot.md)）由宿主创建，元数据由宿主重新给出。
- 工作区仍然不进入内核：参考 CLI 把工作目录写进元数据，是宿主自己的约定；`ToolContext`、工具与沙箱不读它。

键值的数量与长度上限是存储参数，见设计文档。

## Consequences

- 宿主可以只靠框架目录实现"按目录续会话"和按名字查找，不需要第二份真相源；日志崩溃恢复后元数据与会话同在。
- `SessionStore` 的目录项多一个字段，每个存储适配器都要保存它；契约套件随之扩展。
- 改名、打标签这类可变需求做不到；需要时宿主自建索引，或者另写 ADR 引入修改记录。
- 发布前改动，`LOG_SCHEMA_VERSION` 不变。

## Considered alternatives

- **宿主在数据库旁自建索引**：内核不改，但多一份真相源；会话已写入、索引未写入时崩溃，会话就从列表里消失。
- **工作目录作为内核一等字段**：内核要定义"工作区"的语义（规范化、多根、可移动），而多数嵌入者根本没有工作目录。
- **可变元数据**：要多一种会话事件与它的折叠规则，只为改名一个场景。
- **只按时间列出、不过滤**：与两个参照工具的行为不一致，多项目用户无法用 `--continue`。
