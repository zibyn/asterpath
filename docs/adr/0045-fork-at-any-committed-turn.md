# 会话分叉可指定任一已提交回合为水位

**Status**: accepted (2026-10-28)
**部分取代**: [ADR-0033](0033-session-fork-reuses-context-fork-snapshot.md) 的「水位是源会话最后一个已提交回合的末尾」
**来源**: [#167](https://github.com/zibyn/asterpath/issues/167)（拆自 [#157](https://github.com/zibyn/asterpath/issues/157)）

## Context

ADR-0033 把分叉水位固定在最后一个已提交回合的末尾。桌面端需要「回退到这里」：从历史上某个回合重新开始。日志只追加（[ADR-0002](0002-log-topology-and-commit-semantics.md)），不能原地截断。

## Decision

- **分叉可指定源会话任一已提交回合**，水位是该回合提交记录的位置；不指定时仍是最后一个已提交回合。
- **投影与生效配置都在该水位处折叠**，规则同 ADR-0033（继承不收窄、基线 system 加追加指令、去掉工具变更条目）。水位在源会话之后某次压缩之前也可以：源日志完整，水位处的投影本身成立。
- 指定的回合不存在或未提交时返回错误。
- **「回退」是分叉加宿主切换**：源会话保持不动，宿主可用元数据把它标为归档（[ADR-0044](0044-host-metadata-is-patchable.md)）。

## Consequences

- 回退不破坏日志的只追加性质，原会话随时可回看。
- 每次回退多一个会话；会话清理归宿主（退役）。

## Considered alternatives

- **原地截断源会话**：违背只追加日志，并破坏恢复与用量。
- **在源会话里写「回退标记」让投影跳过之后的回合**：投影规则多一种分支，用量与追踪要区分被跳过的回合。
