# 结构化输出有显式选择的输出模式，工具模式由引擎以输出工具实现

**Status**: accepted (2026-10-25)
**来源**: [#127](https://github.com/zibyn/asterpath/issues/127)
**修订**: [ADR-0031](0031-server-tools-structured-output-and-file-input.md) 的结构化输出（产出不再只是消息文本）

## Context

ADR-0031 把结构化输出定为请求约束：adapter 把 schema 渲染成供应商的原生约束（`text.format` / `output_config.format`），模型不支持就在发出 HTTP 前返回 `Unsupported`。不少第三方端点支持工具调用，却不支持原生 schema 约束，例如 DeepSeek 的 Anthropic 端点会忽略 `output_config.format`。这类端点只能拿到报错。

其他框架有三类做法：不降级、直接失败（OpenAI Agents SDK、LiteLLM 默认）；由调用方显式选择模式（LangChain `method`、Instructor `Mode`、Pydantic AI 输出模式，Pydantic AI 默认用工具模式）；自动降级（AI SDK 改发 `json_object`，ADK 注入结果工具）。

约束：
- ADR-0010 不静默降级：能力不支持时返回 `Unsupported`，不换成更弱的约束。
- 供应商要求每个工具调用后跟一个工具结果，否则下一回合回放会被拒绝。
- 规范化不改变语义：日志如实记录模型做了什么。
- 工具集指纹近似 Anthropic 对 `tools` 变化的校验（ADR-0030）。
- 解析、校验与重试是宿主策略（ADR-0031）。

## Decision

- **输出模式由宿主显式选择**：原生、工具、自动三种，默认原生。只有约束强度相同的实现；只要求 JSON 的 `json_object` 和只写进指令的 prompted 方式不提供。
- **自动模式按每次请求的模型能力解析**：模型支持原生 schema 就用原生；否则支持强制工具选择就用工具；两者都不支持返回 `Unsupported`。会话中途换模型时，模式可能随之切换。
- **工具模式由引擎实现，adapter 不知道有这个模式**：引擎把输出工具作为普通函数工具加入本次请求，把工具选择设为"必须调用某个工具"。模型可以在输出工具和其他工具（客户端工具与服务端工具）之间自由选择，不能只回纯文本。loop 只按能力标志分支（ADR-0010）。
- **输出工具调用如实落日志**：调用的意图以独立的来源（输出）记录。崩溃恢复时据此识别，不依赖当时的配置。框架补一条固定内容的成功结果，回合以 `Completed` 结束。结果就是这次调用的参数；输出工具不经工具执行管线，不审批、不执行。
- **同一步的其他工具照常执行**：模型在同一步里同时调用了输出工具和其他工具时，其他工具照常审批、执行，这一步结束后回合就结束，不再请求模型。多个输出工具调用按位置取第一个作为结果，其余也补上同样的结果。
- **框架仍不解析、不校验、不重试**：端点忽略强制工具选择、直接回了文本时，回合照常结束，结果视为未交付，由宿主判断。
- **输出工具计入工具集指纹**：自动模式下切换模式按工具变更处理（ADR-0030）。
- **宿主的工具选择与工具模式矛盾时**（禁止调用工具，或指定了其他工具），工具模式报配置错误，自动模式改用原生。

## Consequences

- 支持工具调用的第三方端点可以拿到受 schema 约束的结果，adapter 不用改。
- 宿主读取结果的位置取决于实际模式：原生模式在最后一条 assistant 消息的文本里，工具模式在输出工具调用的参数里。
- 日志里多了一种工具调用来源。旧日志不受影响，因为没有选择模式的配置会解码为原生。
- 工具模式下，与输出工具同一步发出的工具调用，其结果模型看不到。
- 自动模式下，同一会话的历史里可能同时出现文本结果和输出工具调用。

## Considered alternatives

- **自动降级到 `json_object` 或 prompted**：约束变弱而宿主不知情，违反 ADR-0010。
- **在 adapter 里实现工具模式，并把调用改写成文本**：两个 adapter 各写一遍，还要改写模型实际的输出，违反规范化不改变语义。
- **每一步都把工具选择强制指向输出工具**：模型不能再调用其他工具，agent 退化成单步提取。
- **同一步的其他调用不执行**：需要新增一种结局类型；而且模型既然发出了这些调用，审批已经能把关。
- **不记录输出工具调用的意图，恢复时按配置里的名字匹配**：中途改过配置就会认错。
- **新增"结果未交付"的结束原因**：让框架开始判断结果有没有交付，往校验方向又走了一步。
