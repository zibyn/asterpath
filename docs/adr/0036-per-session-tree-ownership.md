# 写者独占缩小到会话树：显式认领、属主纪元，多进程共用一个存储

**Status**: proposed (2026-10-25)
**部分取代**: [ADR-0023](0023-storage-holds-log-and-catalog-wake-by-fold.md) 的「单进程独占写者」
**调研**: [multi-process-storage-audit.md](../research/multi-process-storage-audit.md)、[design-audit-2026-10-25.md](../research/design-audit-2026-10-25.md)

## Context

ADR-0023 规定一个存储只有一个写进程，第二个进程打开即失败。CLI、桌面与 web 都把内核作为库内嵌，是同一内核的不同形态，数据必须互通：CLI 与桌面要能同时打开同一个库，web 服务要能滚动重启。整库独占挡住了这些。

日志顺序只要求同一会话内单写；seq、去重、读写都以会话为单位，没有跨会话的原子性要求。子会话由父会话的进程直接驱动，孤儿判定与退役都读父会话，所以最小的独占单位是一棵会话树。

引擎在 drive 时看到未闭合回合，就认定上一个驱动者已崩溃并开始恢复。因此任何驱动、压缩或子会话调度之前都必须确定自己是唯一驱动者；今天这只靠进程内的 busy 集合。

参考产品没有现成答案：pi-durable 让整个存储只有一个属主，opencode 用「每用户一个服务进程」绕开，Claude Code 与 pi 不加锁。

## Decision

- **属主以会话树为单位**：根会话 id 是归属键，子会话随根会话归属。同一时刻至多一个属主；不同会话树可由不同进程并行持有。
- **显式认领**：打开会话得到只读句柄（投影、事实、目录、订阅）；驱动、手动压缩、调度子会话要先认领，得到属主句柄，drop 即释放。被他人持有时返回 `OwnedElsewhere`。提供 `owner(session)` 查询，宿主据此把需要属主的操作路由过去。
- **写入分两类**：
  - **属主写入**（agent loop、压缩、子会话调度产生的记录）携带属主凭证，存储拒绝过期纪元的写入；
  - **外部写入**（用户输入、审批决定、配置变更、取消请求）任何进程都可以写，靠去重键保证幂等，由属主在步骤边界折叠进来。
- **属主纪元进合约**：每次认领纪元递增。不引入心跳租约；属主死亡由后端原生机制释放（SQLite 用进程级锁，Postgres 用会话级锁）。
- **跨进程审批与取消走日志**：非属主写入的审批决定与取消请求落日志，属主在驱动与等待期间有上限地轮询日志。取消请求指向一个未闭合回合，回合已闭合则忽略；属主崩溃时未执行的取消请求在恢复时按取消收尾。待审批从日志折叠，见 ADR-0042。
- **唤醒发现只返回无主会话**；哪个进程认领哪些会话由宿主决定。
- **前置修复**：会话与输入 id 改为随机生成，不依赖进程内计数；退役后 append 被拒绝；并发首次打开时建表幂等。
- **降级语义写进文档**：`max_live_children` 是每进程上限；提交回调在每个进程内恰好一次，跨进程可能重复，宿主按 (session, log_id) 去重；属主迁移时清掉调度器的恢复缓存。

SQLite 的锁文件、`busy_timeout` 与重试、建表并发见 storage.md。

## Consequences

- CLI 与桌面端可同时运行，同一会话一端驱动、另一端只读观察。
- 规模靠单进程：一个进程内由 writer 线程合并提交，服务上千会话；多进程之间没有合并提交，各自 fsync，只用于共存与滚动重启。多设备共用存储需要 Postgres 后端。
- 跨进程的审批决定与取消有轮询延迟，存储变更通知（[#160](https://github.com/zibyn/asterpath/issues/160)）可以替代轮询；询问落日志后任何进程都能看到待审批（[ADR-0042](0042-approval-asks-are-logged.md)）。
- 合约多了属主凭证、`owner` 查询与 `OwnedElsewhere`，所有后端和 contract suite 都要跟进。
- 上千会话时按全量折叠发现唤醒太慢；改为索引需要另一份 ADR 修订 ADR-0023 的「不物化派生状态」。

## Considered alternatives

- **保留整库独占，各形态各用一个库**：数据不通。
- **整个存储单属主、其他进程只读**（pi-durable）：CLI 与桌面端不能同时驱动各自的会话。
- **每用户一个服务进程，其他形态连它**（opencode v2）：要求先有线协议，也不适合单进程多用户的 web 内嵌。
- **独占单位是单个会话**：子会话由父会话进程驱动，拆开会出现跨进程的父子协调。
- **drive 时隐式认领**：只读观察也会抢走归属。
- **心跳租约**：多一个故障面；后端原生锁加纪元已足以防止双写。
- **所有写入都要求属主**：用户输入和审批决定就必须路由到属主进程，宿主要先有进程间通讯。
