# 会话分叉复用上下文分叉的快照

**Status**: accepted (2026-10-24)；水位固定为最后已提交回合部分取代 by [ADR-0045](0045-fork-at-any-committed-turn.md)（proposed）
**来源**: CLI 重设计（[packaging.md](../design/packaging.md) §4，[对比研究](../research/cli-codex-vs-claude-code.md)）
**扩展**: [ADR-0008](0008-subagent-model.md) 的 fork 快照（来源不再只是 spawn 调用）

## Context

Codex（`fork`）与 Claude Code（`--fork-session`）都允许从一个已有会话分出新会话：保留到某时刻的上下文，之后各走各的。Asterpath 已有一个相近机制：子会话的上下文分叉把父会话在 spawn 所在 step 水位的投影物化进子流，记为 `ContextForked { source, source_log, items }`，其中 `source` 是父会话、回合与 spawn 工具调用。

宿主发起的分叉没有父回合，也没有工具调用，套不进 `source`；它也不是子会话，不该等待、返回任务总结或参与取消传播。

## Decision

- **会话分叉是宿主创建的独立会话**，以源会话某时刻的投影快照为初始历史；没有父会话，不进入源会话的会话树，不返回任务总结。
- **复用 `ContextForked`**：`source` 改为分叉来源的枚举，区分"spawn 调用"（现有语义）与"宿主分叉"（源会话 + 源日志位置）。投影、压缩与恢复对两种来源一视同仁。
- **水位是源会话最后一个已提交回合的末尾**；进行中的回合不复制，源会话正在被驱动时也可以分叉。
- **配置按上下文分叉的同一套规则继承，只是不收窄**：模型、请求参数与生效工具集取源会话在水位处的生效配置；system 取分叉点的基线 system 加分叉点之后追加的指令；复制的历史去掉工具变更条目。之后宿主可以对新会话照常 `update_config`。
- **快照物化进新会话的日志**：源会话之后的压缩、退役或删除不影响分叉。

## Consequences

- 宿主用一次调用就能"从这里重来"，保留模型可见历史；新会话有自己的身份、用量与子会话树。
- 源会话的用量不复制；分叉后的用量只归新会话。快照复制一次上下文，成本受源会话上下文窗口约束。
- `ContextForked` 的 `source` 字段形状改变；发布前改动，`LOG_SCHEMA_VERSION` 不变。
- 不透明 reasoning 按既有绑定门控回放；跨模型分叉时自然丢弃。

## Considered alternatives

- **新增 `SessionForked` 事件**：语义更直白，但投影、压缩与恢复要为同一份快照处理两种事件。
- **复制原始日志记录**：保留全部细节，但要重写会话 id 与水位，并把源会话的意图与等待一起带过来，恢复语义变复杂。
- **分叉作为子会话**：会话树与取消传播把两个应当独立的会话绑在一起。
- **允许任意水位**：宿主能挑回合中间的点，但会复制出未闭合的意图；按已提交回合末尾切开没有这个问题。
