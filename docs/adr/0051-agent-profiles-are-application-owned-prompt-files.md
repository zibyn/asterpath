# 智能体档案是应用的命名提示词文件，会话创建时解析一次

**Status**: accepted (2026-10-26)
**来源**: [#181](https://github.com/zibyn/asterpath/issues/181)、[#182](https://github.com/zibyn/asterpath/issues/182)
**调研**: [prompt-injection-and-caching.md](../research/prompt-injection-and-caching.md)

## Context

本地应用（CLI 与桌面端，ADR-0049）新建会话时，system 只有工作根下 `AGENTS.md` 的原文和技能索引，没有基础提示词，也没有地方配置。框架内核不带默认提示词（ADR-0048），所以基础提示词由应用提供。

需求是「不同的人、不同的职业配不同的提示词」：写代码、写文档、做审阅各要一套。参照产品都用**命名档案**解决：opencode 的 agents、Claude Code 的 subagents 与 `--agent`、Copilot 的 custom agents、Codex 的 profiles。按模型切换的提示词各家都由厂商在内部维护，不交给用户（调研 §0）。

还要守住两条已有约束：

- **缓存前缀稳定**：system 在会话里不变，会话中途的变化以日志里的配置变更追加（ADR-0030）。档案若在恢复时重新读文件，用户改了档案文件，旧会话的前缀就变了。
- **项目目录不可信**：项目级的内容（`AGENTS.md`、`.asterpath/skills`）随仓库来，可能来自别人。用户配置只有用户级一层，审批与沙箱策略不受项目目录影响。

## Decision

- **智能体档案是一个命名的 Markdown 文件**：frontmatter 是元数据（如描述、固定的模型、工具收窄），正文是基础提示词。档案属于应用，不进框架内核与门面（ADR-0048、0049）。档案与「模型规则」（ADR-0029，adapter 对某个模型的请求规则）无关。
- **不提供按模型配置的提示词**：档案可以固定一个模型；没固定时用配置里的模型。
- **档案只替换基础提示词**：`AGENTS.md` 与技能索引照常拼在档案正文之后。
- **两级来源，同名时项目级优先**：用户级 `$XDG_CONFIG_HOME/asterpath/agents/`，项目级 `<root>/.asterpath/agents/`。文件名（去掉 `.md`）就是档案名。
- **内置默认档案是随安装包分发的资源文件**，不编进二进制；用户级或项目级的同名档案覆盖它。
- **会话创建时解析一次**：选中的档案在创建会话时读取、组装进初始配置，随 `SessionCreated` 落盘。恢复会话不重新读档案，与 `AGENTS.md` 一致。会话中途不切换档案。
- **项目级档案不能放宽权限**：它可以替换提示词、收窄工具，不能放宽审批与沙箱；frontmatter 里放宽这两者的字段在项目级档案中是错误。

## Consequences

- 用户可以按职业维护几份档案，在 CLI 或桌面端新建会话时选；`config.toml` 只需记默认用哪一份。
- 改档案文件只影响之后新建的会话；旧会话的前缀与恢复结果不变，代价是改了档案的用户要新开会话才能看到效果。
- 内置默认档案作为资源文件，可以不重新编译就修改，用户也能直接看到它的内容并以同名文件覆盖；代价是安装包要带上资源目录，找不到资源时应用要有明确的报错或回退。
- 项目级档案与 `AGENTS.md` 一样会进 system，克隆来的仓库能改变模型看到的提示词，但拿不到更宽的审批或沙箱。
- 子智能体按档案名生成、只换语气的叠加档案都可以以后在本 ADR 之上加，不改解析时机与优先级。

## Considered alternatives

- **按模型配置提示词**：用户很难为每个模型维护提示词，各家也不这样做；模型差异由 adapter 与模型规则处理。档案固定模型已覆盖「某份提示词只配某个模型」的需要。
- **档案写进 `config.toml`**：长篇提示词放在 TOML 字符串里难编辑，也无法放进项目目录随仓库共享；独立的 Markdown 文件与技能、`AGENTS.md` 的形态一致。
- **内置默认档案编进二进制**：改内容要重新发版，用户看不到内置的提示词是什么，覆盖时也无从参照。
- **恢复时重新读档案**：会改变已存在会话的缓存前缀，恢复结果也依赖磁盘上的当前文件，与 ADR-0030「变化是历史中的一个位置」相悖。
- **允许会话中途切换档案**：等于在会话中替换 system，要么打掉缓存前缀，要么把切换做成追加的配置变更；需求里没有这一场景，选择不做。
- **项目级档案与用户级同权**：克隆一个仓库就可能被放宽审批或沙箱，与 fail closed 的默认相悖。
