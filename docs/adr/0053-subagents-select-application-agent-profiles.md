# 子智能体可以按名字选用应用提供的智能体档案

**Status**: accepted (2026-10-26)；部分取代 [ADR-0008](0008-subagent-model.md)「不能替换 system」
**来源**: [#181](https://github.com/zibyn/asterpath/issues/181)、[#187](https://github.com/zibyn/asterpath/issues/187)

## Context

ADR-0008 规定 spawn 的模型可见参数只能收窄（模型别名、工具集），不能放宽审批，也不能替换 system。这条规则防的是模型自己写 system 文本：被注入的任务描述可以借此改写子智能体的身份与约束。

智能体档案（ADR-0051）让应用为不同职能准备命名的基础提示词。委托任务时，父会话的模型常常需要一个专门的子智能体（审阅、检索、写文档），而子会话现在只能继承父会话的 system。

## Decision

- **模型可以按名字选档案，不能写 system 文本**：`spawn_agent` 的可选参数是一个档案名，只能从应用为该会话提供的档案集合里选；集合之外的名字是参数错误，不创建子会话。安全边界与模型别名相同：选的是应用定义的东西，不是模型生成的内容。
- **审批与沙箱照旧继承父会话**，档案不影响二者。
- 档案属于应用（ADR-0048、ADR-0051）。内核不读档案文件，只提供按名字取用的机制。
- **可选档案是会话环境的一部分**：应用的环境适配器（ADR-0037）按根会话的元数据解析出可选档案的列表，每项包含名字、描述、组装好的 system、可选的固定模型和可选的工具列表。子会话沿用根会话的这份列表。列表和环境的其余部分一样不写进日志；子会话实际使用的配置写进 `ChildSessionSpawned`，恢复时不重新解析。
- **子会话的 system 由应用整份给出**，内核原样采用，不拼接父会话的 system。本地应用的组装方式与根会话相同：档案正文、`AGENTS.md`、技能索引，不加输出风格（ADR-0052），因为子会话的输出是给父会话的模型看的，不直接给人看。
- **档案固定的模型必须和父会话同一个 provider**，否则是参数错误。理由与模型别名相同：继承的请求配置不能跨 provider 迁移。
- **工具只能收窄**：子会话的工具集是父会话当前生效的工具、档案的工具列表与模型给出的 `tool_allowlist` 三者的交集。档案是脱离具体会话写的，列了父会话没有的工具就忽略；`tool_allowlist` 里有未知名字仍然报错。
- **能选哪些档案由应用决定**。本地应用开放根会话能看到的全部档案（内置、用户级、项目级合并后的结果）。项目级档案本来就能替换根会话的提示词，开放给子会话并没有提高它的信任级别。
- **不选档案时行为不变**：子会话继承父会话的 system，而不是改用 `default` 档案。
- **选了档案的子会话总是全新上下文**：即使应用把默认上下文策略配成 fork 也一样。档案代表另一种职能，把父会话的历史（其中带着父会话追加的指令）接在另一份 system 后面，两份意图会混在一起；而 fork 的 system 本来就是按父会话的 system 基线算出来的。
- **模型从 system 里的档案索引得知可选档案**：应用把可选档案的名字和描述写成一段索引，放进 system，做法与技能索引相同（ADR-0021）。`spawn_agent` 的描述是固定的，只多一个档案名参数，不列举档案。索引随会话创建写进日志，缓存前缀不变；spawn 时按名字查当前环境，名字已不在列表里就是参数错误。子会话的 system 带同一份索引，嵌套深度由已有的深度上限约束。
- **档案固定了模型，模型就不能再给模型别名**，两者同时出现是参数错误，以免模型以为自己换了模型，实际却没有换。档案没有固定模型时，别名照常生效。
- **选用了哪个档案不另行记录**：父会话 spawn 调用的参数里已有档案名。

## Considered alternatives

- **由父档案或配置给子会话固定档案，模型不能选**：失去按任务挑选专门子智能体的价值。参照产品（Claude Code 的 subagent 类型、opencode 的 agents）都由模型按名字选。
- **builder 上的固定档案表**（与模型别名同形）：档案有项目级，一个进程里不同根目录的档案不同，固定表放不下。
- **spawn 时按名字回调应用的新 trait**：模型事先要知道有哪些档案，列表终归要提前拿到，单独的 trait 是多余的。
- **内核在 `spawn_agent` 描述里按会话列举档案**：工具描述要随环境变化，而环境每次打开都重新解析，会和日志里的描述对不上，还会牵动工具集指纹（ADR-0030）。
- **档案固定模型时静默忽略模型别名**：模型以为换了模型，实际没有。
- **档案跨 provider 时重置请求配置**：内核要多一套迁移请求配置的逻辑，目前没有这个需求。
- **选了档案仍然遵循 fork 默认**：档案 system 后面接父会话的历史，父子的指令会混在一起。
- **选了档案又配置了 fork 就报错**：配了 fork 的应用就完全用不了档案。
- **不做**：子会话只能继承父会话的 system，委托出去的任务没法换成专门的提示词。
