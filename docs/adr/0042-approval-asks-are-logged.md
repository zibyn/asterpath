# 询问落日志，待审批从日志折叠；宿主可声明持久审批端点

**Status**: proposed (2026-10-25)
**部分取代**: [ADR-0007](0007-approval-and-sandbox-layers.md) 的「询问不是持久事实」与「没有审批端就 fail closed」
**来源**: [#159](https://github.com/zibyn/asterpath/issues/159)（拆自 [#155](https://github.com/zibyn/asterpath/issues/155)）

## Context

ADR-0007 让「询问」只活在属主进程里：待审批列表在 `ApprovalGate` 内，只有属主进程注册的审批端点算有人能应答。ADR-0036 之后，输入、审批决定、取消请求都已是任何进程可写的外部写入，只剩询问绑在属主进程上。

多台机器共用一个 Postgres 存储时，用户的连接不一定落在属主节点。按会话树粘滞路由能绕过去，但把「谁执行」和「谁能处理请求」绑在一起：属主宕机或迁移期间，任何节点都答不出「这个会话有哪些待审批」，路由与属主不一致时还要转发兜底，正确性依赖路由层。ADR-0007 当初否决「询问落日志」的理由是「为一个 UI 问题持久化询问」；多机部署下这是可用性问题。

## Decision

- **询问落日志**：策略判定为 `Ask` 时，属主追加一条审批请求记录（属主写入，带纪元），以工具调用 id 去重，恢复时不重复写。记录只带调用 id 与当时的副作用等级；工具名、参数等已在工具调用意图里。实时 `ApprovalRequested` 事件照常发给驱动者。
- **待审批由折叠得出**：有审批请求记录、无审批决定、工具调用意图仍未闭合。意图闭合（执行、拒绝、取消、中断，或恢复时策略已改为允许或拒绝）后自然不再待审批，不需要单独的闭合记录。任何进程都能从只读句柄查询。
- **持久审批端点**：宿主可以声明「审批决定会经日志由任意进程写入」。注册后 `Ask` 总是记录并等待；不注册时保持 fail closed。
- **并发决定先写者胜**：同一调用的重复决定，与已有决定相同则成功，不同则返回已有决定，调用方据此刷新。

## Consequences

- 处理审批的节点不需要是属主；粘滞路由降为性能优化，不再是正确性依赖。执行仍由每棵会话树唯一的属主负责（ADR-0036）。
- 每次 `Ask` 多一次 append。
- 注册了持久审批端点却无人应答时，步骤会一直开着；ADR-0007 已接受步骤可以跨天开着，取消照常可用。
- 跨节点看到新的询问有轮询延迟，存储变更通知（[#160](https://github.com/zibyn/asterpath/issues/160)）可替代轮询。
- 进程内的 `ApprovalGate::pending()` 保留，用于汇总本进程内的待审批。

## Considered alternatives

- **按会话树粘滞路由，询问留在属主进程**：属主宕机或迁移期间待审批不可见，正确性依赖路由层与转发。
- **审批端点跨进程登记**：要有存活判定，等于引入心跳租约。
- **专门的询问闭合记录**：意图闭合已经蕴含询问结束，多一种记录只会多一种不一致。
