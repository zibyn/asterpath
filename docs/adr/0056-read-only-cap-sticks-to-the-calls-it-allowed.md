# 因只读上限而放行的调用保留这个上限

**Status**: accepted (2026-10-27)；部分取代 [ADR-0055](0055-sandbox-is-the-boundary-for-spawned-commands.md)「模式切换立即生效；启动进程时总按当前模式收紧」与其否决「按回合快照模式」的理由
**来源**: [#193](https://github.com/zibyn/asterpath/issues/193)、[#194](https://github.com/zibyn/asterpath/issues/194)

## Context

ADR-0055 里审批模式是「沙箱外调用的结论 + 沙箱策略上限」，审批与启动进程是两个时刻：审批按当时的模式给结论，`bash` 启动时再按当时的模式收紧沙箱。ADR-0055 认为模式只收紧，所以切换立即生效不会让本该询问的调用被放行。

这不成立。配置的沙箱是 `full-access`、有可用后端时，只读模式下 `bash` 被允许，理由仅仅是它会被收紧到 `ReadOnly`。审批之后、启动之前若切到询问或放行模式，启动时不再收紧，这条调用就不受限地执行了：询问模式下它本该询问。

## Decision

- **结论依赖只读上限的调用，启动时保留上限**：应用的审批策略因只读上限而允许一条 `bash` 调用时，按会话树记下它的调用 id；启动时，当前模式是只读或调用 id 被记下（取出即删除），都收紧到 `ReadOnly`。其余调用仍按启动时的模式收紧。
- 记录在应用的审批策略里，与模式一样只在内存中；内核不新增钩子，策略照旧写进 `ctx.spawn.sandbox`。

## Consequences

- 模式切换仍立即生效，但只会让结果更严：放宽模式不会放宽已按只读批准的调用。
- 记录不持久：审批后、启动前应用重启，恢复的调用按重启后的模式启动（模式本身也回到默认）。未启动就结束的调用会留下一条记录，直到应用退出。

## Considered alternatives

- **按回合快照模式**：同样能堵住，但切到只读时已批准的调用也按快照执行，失去「切到只读立即生效」。
- **审批结论携带收紧后的沙箱策略**：ADR-0055 已否决，把两层重新绑进一个内核类型。
